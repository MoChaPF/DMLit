# WEIKAV VEGA108 键盘技术手册

> 面向开发者与折腾党。记录这把键盘的硬件、私有 HID 协议、灯效体系、改键接口和已知的坑。
> 参考 QMK 文档的组织方式，但 **VEGA108 不是 QMK/VIA 键盘**：主控是华奋达定制 SoC，协议为厂商私有，固件加密不可替换。本文所有结论都来自实测与逆向，未验证的部分会明确标注「待确认」。

---

## 1. 概述

| 项目 | 内容 |
|---|---|
| 品牌 / 型号 | WEIKAV（维咖）VEGA108 |
| 配列 | 108 键全尺寸（带独立功能区 + 数字小键盘） |
| 连接 | 三模：USB 有线 / 2.4G 无线 / 蓝牙（蓝牙部分本文未覆盖） |
| 主控 | 华奋达（HFD）定制 SoC，型号标 HFDQKJ801 |
| 外部存储 | PUYA P25Q05A，512 Kbit SPI NOR，存配置不存固件 |
| 灯效 | 逐键 RGB，128 路（不是 108 路，见 §4.2） |
| 官方工具 | 网页驱动 `weikav.driveall.cn`、Windows 升级工具 HFD_IAPTool |

### 1.1 是不是 QMK / VIA

不是。用 VIA 作者的工具查过，识别不出来。这意味着：

- 不能刷 QMK 固件，不能用 VIA 改键
- 官方固件是加密的（升级包里 743 KB 有效数据，无字符串、无 ARM 向量表、非压缩格式），**固件级魔改这条路基本堵死**
- 所有可定制能力都要走 §3 的私有 HID 协议，在电脑侧实现

## 2. 硬件与连接

### 2.1 USB 身份

- VID：`0x0C45`（Sonix 系，华奋达常用）
- 有线 PID：`0x8802`
- 2.4G 接收器 PID：`0xFEF9`

有线模式下会枚举出 4 个接口，按 usage page 区分：

| 接口 | usage page | 用途 | 报告长度 |
|---|---|---|---|
| mi_01 | `0x0001` | 键盘 HID（标准键值） | 2 / — |
| mi_02 | `0xFF67` | 厂商通道 A | in 65 / **out 4105** |
| mi_03 | `0xFF68` | 灯效通道（主用） | 65 / 65 |
| mi_04 | `0xFF70` | 厂商通道 B（用途待确认） | 65 / 65 |

`0xFF67` 的 4105 字节输出报告 = 4096 + 9，是**固件升级/大块数据传输**用的通道。2.4G 接收器没有这个接口，所以升级只能在有线模式做。

无线模式下灯效走 `0xFF60`（usage page `0xFF60`，usage `0x61`）。

### 2.2 进入升级模式

有线连接 → 按 `Fn + T` → 键盘进入 IAP 模式 → 运行官方升级工具（HFD_IAPTool）。中途拔线或用无线都会失败。

## 3. 通信协议

### 3.1 帧格式

发往键盘（65 字节，含 report id）：

| 偏移 | 含义 |
|---|---|
| `p[0]` | report id，固定 `0x00` |
| `p[1]` | 帧头 `0xAA` |
| `p[2]` | 命令号 |
| `p[3]` | 数据长度 |
| `p[4..5]` | 地址（低字节在前） |
| `p[7]` | 固定 `1` |
| `p[9..]` | 数据区 |

键盘返回（`0x55` 开头，可能带 report id，需要判断 base）：

| 偏移 | 含义 |
|---|---|
| `r[base]` | 响应头 `0x55` |
| `r[base+1]` | 命令号（回显） |
| `r[base+2]` | 长度 |
| `r[base+8..]` | 数据区 |

`base = 0 if r[0] == 0x55 else 1`。读响应时建议「发一次 → 连读几包 → 挑命令号和地址匹配的那包」，设备响应会滞后一包。

### 3.2 命令速查

逆向自官方网页驱动的协议常量表（完整表见附录 A）：

| 命令 | 编号 | 方向 |
|---|---|---|
| `GET_DEVICE_INFO` | 16 | 读 |
| `GET_LED_EFFECT` | 19 | 读当前灯效 |
| `GET_CUSTOM_LED_DATA` | 20 | 读逐灯颜色 |
| `GET_KEY` | 18 | 读键值 |
| `GET_MACRO` | 21 | 读宏 |
| `SET_LED_EFFECT` | 35 | 写灯效 |
| `SET_CUSTOM_LED_DATA` | 36 | 写逐灯颜色（持久） |
| `SET_KEY` | 34 | 写键值 |
| `SET_MACRO` | 37 | 写宏 |
| `SET_SIDE_LIGHT` | 45 | 侧灯 |
| `GET_ALL_LIGHTS_RGB` | 51 | 读全灯颜色（有线） |
| `SET_MUSIC_DATA` | 53 | 音乐律动数据 |
| `SET_LED_DATA` | 66 | 写灯数据 |
| `GET_ALL_LIGHTS_RGB_24G_64_BYTE` | 59 | 无线读色 + 电量 |
| `SET_MUSIC_DATA_24G_64_BYTE` | 60 | 无线推灯 |

### 3.3 灯效写入（SET_LED_EFFECT = 35）

数据区 24 字节，布局：

```
mode, r, g, b, driverSetting, secR, secG, secB, colorMode, brightness, speed, direction
```

**`driverSetting` 必须是 255**，否则无线通道整包丢弃，有线通道行为也会异常。

- `colorMode = 1` 表示 RGB 模式，固件会忽略传入的 rgb
- `mode = 128` 是「软件接管」的临时模式，不持久（见 §4.3）
- `mode = 20` 是固件自己的「自定义」灯效，持久（见 §4.2）

### 3.4 逐灯数据（SET_CUSTOM_LED_DATA = 36）

512 字节 = 128 灯 × 4 字节：

```
[ledId, r, g, b] × 128
```

`ledId` 就是灯序 0..127。分包发送（每包 56 或 64 字节，靠地址累加）。

**这是唯一持久的方式**。用临时通道（cmd 50）写进去，几秒后会被固件动画覆盖回去。

### 3.5 无线通道（2.4G，usage page 0xFF60）

- **读色**：`cmd 59`，参数是 ledId 列表（uint16 小端），响应里 RGB565 **大端**存于 `r[9]` 起；电量在 `r[6]`
- **推灯**：`cmd 60`，每灯 RGB565（大端），56 字节一包
- **限制**：读 `cmd 19`（当前灯效）在无线通道上会长时间超时，程序应跳过不读，靠本地保存的状态回填 UI

## 4. 灯效体系

### 4.1 固件内置灯效（1–19）

| 模式 | 名称 | 备注 |
|---|---|---|
| 1 | 静态恒亮 | 单色，吃亮度 |
| 2 | 单点亮 | 按键触发 |
| 3 | 单熄灭 | 按键触发 |
| 4 | 繁星点点 | 自带颜色 |
| 5 | 漫天飞雪 | 自带颜色 |
| 6 | 百花争艳 | 强制 RGB |
| 7 | 动态呼吸 | 单色，吃速度 |
| 8 | 光谱循环 | 强制 RGB |
| 9 | 彩泉涌动 | 自带颜色 |
| 10 | 多彩纵横 | 自带颜色 |
| 11 | 随波逐流 | 自带颜色 |
| 12 | 彩虹风车 | 自带颜色 |
| 13 | 一触即发 | 按键触发 |
| 14 | 一石二鸟 | 按键触发 |
| 15 | 涟漪扩散 | 按键触发 |
| 16 | 川流不息 | 自带颜色 |
| 17 | 重峦叠嶂 | 自带颜色 |
| 18 | 斜风细雨 | 自带颜色 |
| 19 | 来回穿梭 | 自带颜色 |

RGB 类模式（4/5/6/8/10–20）不吃基础色，传颜色会被内部彩虹覆盖。速度对静态类（1/2/3）无效。

### 4.2 自定义灯效（20）

键盘自己的「自定义」模式。进这个模式后，键盘停止播放动画，改为显示上一次写入的逐灯颜色。

- 写入命令：`SET_CUSTOM_LED_DATA (36)`
- 数据：512 字节（§3.4）
- 持久：断电、切模式都不丢
- 灯数：**128**。键位只有 108 个，多出来的 20 路推测是侧灯、指示灯或未装配位（待确认），逐灯写入时统一按 128 处理

### 4.3 软件接管（128）

`mode = 128` 让固件进入「软件说啥就是啥」的状态，配合临时数据通道（cmd 50）可以做任意动画，比如音乐律动、涟漪、画板预览。

**特性与代价**：
- 刷新率高，适合 30fps 级别的动画
- **不持久**：停止推送几秒后固件动画会盖回来
- 所以：短暂预览、实时动画用 128 + cmd 50；要留住颜色用 20 + cmd 36
- 实测写临时数据的通道是 `cmd 50`（官方常量为 `GET_LED_DATA`，名字是读，但写数据同样生效，数据布局同 §3.4）

### 4.4 音乐律动

采集系统播放音频（`soundcard` 回环），做 FFT 后映射成逐灯颜色，用 cmd 50 以 30fps 推给键盘。

四种展示：柱状频谱 / 块状火山 / 彩虹波 / RGB 脉冲。

## 5. 改键与宏

### 5.1 键值（SET_KEY = 34 / GET_KEY = 18）

**写入**：`SET_KEY(34)` 一次 512 字节，每个键 4 字节：

```
[pageType, param1, param2, param3]
```

下标是 `键的 value × 4`（`value` 来自 `vega108_layout.json`，即 LED 编号）。没改过的键写 `0,0,0,0`。

**pageType 枚举**：

| pageType | 名称 | 含义 |
|---|---|---|
| 0 | DEFAULT | 默认（不覆盖） |
| 1 | MOUSE | 鼠标动作 |
| 2 | KEYBOARD | 普通键盘键码 |
| 3 | CONSUMER_KEY | 媒体键（音量/播放等） |
| 4 | SYSTEM_KEY | 系统键（电源/睡眠等） |
| 5 | EXTRA_FUNCTION | 扩展功能 |
| 6 | MACRO | 宏 |
| 7 | CB | 组合键 |
| 8 | DKS | 双击（哪种动作待确认） |
| 9 | MT | Mod-Tap（按住修饰，点按普通键） |
| 10 | TGL | 切换（Toggle） |
| 11 | SOCD | SOCD 清除（游戏用） |
| 12 | RS | Rapid Switch（连发） |
| 13 | FUNC | 功能键 |
| 14 | END | 结束标记 |
| 15 | MPT | 多点触发 |

**各类型编码规则**（写进那 4 字节）：

```
DEFAULT        : 0 0 0 0
MOUSE          : [1, param1||1, value||0, 0]
KEYBOARD       : [2, 0, value||0, 0]                  value = HID usage code
CONSUMER_KEY   : [3, value&255, (value>>8)&255, 0]
MACRO/MT/SOCD/RS/CB/MPT : [pageType, param1, param2, param3]
DKS            : [8, value||0, 0, 0]
TGL            : [10, value||0, 0, 0]
FUNC           : [13, (value>>16)&255, (value>>8)&255, value&255]
END            : [14, param1, param2, 0]
```

`pageType >= 128` 是扩展键类型（组合/宏扩展），第 0 字节最高位置 1，后三字节存参数。

**读取**：`GET_KEY(18)` 用自定义 8 字节帧头，不走默认帧：

```
头: AA 12 04 (value*4)&FF (value*4)>>8 00 00 00
```

`contentSize = 4`，返回取 `r[8..11]` 这 4 字节，再用 pageType 反解。逐键读要发 108 次，批量读应先 `SET_KEY` 一次全量，再按需读。

**Fn 层**：Fn 层不走 `SET_KEY`，走 `SET_FN_KEY(38)` / `GET_FN_KEY(22)`（具体是整层还是逐键，待抓包）。

键位与 LED 编号对应关系见 `vega108_layout.json`：每行 `{value, name, x, y, w, h}`，`value` 即 LED 编号，也是改键的下标来源。

**实测验证（2026-11-09）**：对 108 个键逐个发 `GET_KEY`，**全部读回**。默认状态下所有键都是 `pageType=2`（KEYBOARD），值就是标准 HID usage：

| 键 | 读回值 | 标准 HID |
|---|---|---|
| Esc | `02 00 29 00` | 0x29 |
| Q | `02 00 14 00` | 0x14 |
| A | `02 00 04 00` | 0x04 |
| L-Shift | `02 00 E1 00` | 0xE1 |
| Num 0 | `02 00 62 00` | 0x62 |

多媒体键是 `pageType=3`（CONSUMER）：音量+ `03 E9 00 00`（0xE9）、静音 `03 E2 00 00`、计算器 `03 92 01 00`（0x192）。

**读响应的坑**：键盘会持续主动推送 `cmd=51` 的灯色包，把 `cmd=18` 的响应淹没在后面。读键值不能「发一次读几包就完事」，要一直收包直到收到 `cmd==18` 的那一包为止（超时 1～1.5 秒），否则会误判成丢包，108 个键里只能读到十几个。

### 5.2 宏（SET_MACRO = 37 / GET_MACRO = 21）

同样存在、未逆向完。宏数据通常是「按键码 + 延时 + 循环次数」的序列，具体格式待抓包确认。

### 5.3 DMLit 目前的状态

DMLit 只做灯效，不碰改键。改键功能留给后续版本。

## 6. 状态与文件

| 文件 | 谁写 | 内容 |
|---|---|---|
| `state.json` | DMLit | `{mode, color, brightness, speed, color_mode, direction}`，每次改设置都写，启动恢复 |
| `vega108_paint.json` | DMLit | `{"ledId": [r,g,b]}`，单键改色的画板数据 |
| `vega108_layout.json` | 静态 | 键位布局，含 LED 编号、键名、坐标 |

注意：`mode` 保存的是固件模式号。如果保存的是 `20`，启动时会恢复成自定义模式；`128` 不写进状态（它是临时态）。

## 7. 工具链

### 7.1 DMLit（本项目）

Python + pywebview + hidapi 的桌面工具。

- `app.py`：HID 通信、灯效引擎、WebView 桥
- `index.html`：界面
- 依赖约束：**pywebview 必须 5.4**。6.x 的 js_api 注入行为变了，5.3.2 的注入流程又不同，只有 5.4 稳定
- 打包：PyInstaller，spec 里必须 `collect_data_files('webview')`，否则 `window.pywebview.api` 是空对象

### 7.2 官方网页驱动

`https://weikav.driveall.cn/`（需浏览器 WebHID 支持）。功能最全，改键、宏、灯效都有，但它和 DMLit 会**抢键盘**：开着网页驱动时，它会周期性重推自己的配色，把 DMLit 写的颜色盖掉。调试时务必关掉。

### 7.3 固件升级工具

`HFD_IAPTool`（华奋达通用烧录器）。内置 4 个 2 MB 固件资源，其中只有一份是真固件（743 KB 有效数据），其余是空壳。无数字签名。

## 8. 排错清单

| 现象 | 原因 | 处理 |
|---|---|---|
| 界面空白、一直「读取中」 | `Api.window` 是 .NET 对象，pywebview 遍历属性时抛 TypeError，js_api 注入中断 | 属性名加下划线（`_window`），避开遍历 |
| 单键改色几秒后回滚 | 用了临时通道（cmd 128 + cmd 50） | 改走 20 号模式 + cmd 36 |
| 启动很慢、窗口卡住 | `Api.__init__` 里同步读电量，读不到时超时十几秒 | 电量读取放后台线程，超时收紧到 300 ms |
| 无线改灯效没反应 | 缺 `driverSetting=255` | 见 §3.3 |
| 颜色被莫名改回去 | 官方网页驱动开着 | 关掉标签页 |
| exe 打开白屏 | 打包漏了 `webview/js` 数据文件 | spec 加 `collect_data_files('webview')` |

### B. 术语

- **逐灯 / per-key**：每颗 LED 单独控制颜色
- **临时数据**：写进 RAM 的灯效数据，断电或固件刷新后丢失
- **自定义模式（20）**：固件内置的「用户颜色」模式，数据持久
- **软件接管（128）**：固件让出灯效控制权，由上位机实时推送

# DMLit 适配指南

> 写给"另一个 AI 助手"看的操作手册。
> 目标：把这个灯效工具从 WEIKAV VEGA108 适配到**任意一把有私有 HID 协议的键盘**。
> 读完你应该能独立完成适配，不需要问原作者。

---

## 0. 你在做什么

DMLit 是一个 Windows 键盘灯效工具：

- **后端**：Python + `hidapi`（ctypes 直接调 Win32），负责和键盘收发数据
- **前端**：`index.html`（HTML/CSS/JS），跑在 pywebview（WebView2）里
- **职责划分**：后端只管 HID 收发和状态，前端负责界面和动画

当前仓库只适配了一把键盘（VEGA108）。你的任务是把它移植到另一把键盘。

**你能改的就三个文件**（其余不用动）：

| 文件 | 改什么 |
|---|---|
| `app.py` | 设备 ID、接口、命令号、帧格式、灯效参数 |
| `index.html` | 键盘图布局渲染、灯效按钮、键码表 |
| `vega108_layout.json` | 键位数据（每个键的 LED 编号/名字/坐标） |

## 1. 先判断能不能适配

适配的前提是**这把键盘有可逆的私有 HID 协议**。按这个顺序判断：

1. **它有官方网页驱动吗？**（`xxx.driveall.cn` 这类）
   - 有 → 协议大概率可逆，继续
   - 没有，但有 Windows 驱动工具 → 可以抓包，继续
2. **它是不是 QMK / VIA 键盘？**
   - 是 → **不要用 DMLit**，直接去 VIA 改键 + QMK 灯效，别重复造轮子
3. **固件加密吗？** 不影响。DMLit 只用运行时协议，不碰固件。

## 2. 需要先收集的四样东西

适配 = 把下面四样东西弄到手，然后填进代码。

### 2.1 键位布局

每个键要知道：

```json
{"value": 33, "name": "Q", "x": 1.25, "y": 2, "w": 1, "h": 1}
```

- `value`：LED 编号 / 键位下标（**最重要**，改键和逐灯推送都用它）
- `name`：键名（用于显示，也用于分组：WASD/数字键/方向键）
- `x/y/w/h`：键盘图上的坐标和尺寸（单位是"键位格"）

**怎么拿**：官方驱动的键盘图 DOM，或者用标准 104/108 键布局表，把 `x/y` 按行排出来。

### 2.2 HID 协议

最低需要知道：

- 设备 VID/PID
- 用哪个 usage page（厂商私有接口，通常是 `0xFF00` 段）
- 帧格式（本次是 `AA + cmd + len + addr + data`）
- 命令号表（读灯效、写灯效、读全灯颜色、逐灯写）
- 分包规则（一次能发多少字节，地址怎么累加）

### 2.3 灯效模式表

键盘固件自带几种灯效、编号是多少、哪些吃颜色、哪些自带彩虹。

```python
RGB_MODES = {4, 5, 6, 8, 10, ...}     # 不吃基础色
NO_SPEED_MODES = {1, 2, 3}            # 吃不到速度
```

### 2.4 连接信息

有线 / 2.4G 接收器的接口不同，读数方式也不同。两套都要摸清，否则插无线就废。

## 3. 协议逆向怎么下手

**别猜，抓包。**

推荐流程：

1. Chrome 打开官方网页驱动，F12 → Console
2. 注入钩子，把 HID 收发打出来：

```js
const orig = HIDDevice.prototype.sendReport;
HIDDevice.prototype.sendReport = function (id, data) {
  console.log('SEND', new Uint8Array(data));
  return orig.call(this, id, data);
};
```

3. 在页面上点一个灯效，看发出去的是什么
4. 对比不同操作，找出"命令号 → 功能"的对应关系
5. 用同样的思路抓"读"（`receiveFeatureReport` / `inputreport` 事件）

抓完拿一个最小脚本验证：打开设备 → 发一包 → 收一包。

## 4. 代码地图（改哪里）

### app.py

| 位置 | 内容 |
|---|---|
| `VID` / `PAGES` | 设备 ID 和接口 usage page |
| `KEYS` | 灯珠总数（不一定等于按键数，多的可能是侧灯） |
| `Keyboard._write` / `_request` | 帧构造，改帧头/字段位置 |
| `Keyboard.set_pixels` | 逐灯推送，改命令号和每灯字节数 |
| `Keyboard.set_mode` | 写灯效，改数据布局 |
| `Api.current_effect` | 读灯效，改响应解析 |
| `Api.battery` | 读电量 |
| `RGB_MODES` 等集合 | 灯效特性 |

### index.html

| 位置 | 内容 |
|---|---|
| `pvKeys` 构建 | 键盘图坐标渲染 |
| `#fwGrid` 里的 `.fx` | 灯效按钮列表（`data-fw` 是模式号） |
| `HID_*` 数组 | 改键的键码表 |
| `KEY_LABEL` | 键名缩写映射 |

## 5. 适配 Checklist（按顺序做，每步验证后再下一步）

- [ ] **1. 抓包**：确认一条能用的命令，记录请求/响应字节
- [ ] **2. 最小脚本**：打开设备 → 发命令 → 收到响应（用 Python + hidapi）
- [ ] **3. 读灯效**：读出当前模式和颜色，打印出来
- [ ] **4. 写灯效**：改一个模式，键盘真的变了
- [ ] **5. 读全灯颜色**：拿到每个灯珠的 RGB（实时预览靠它）
- [ ] **6. 逐灯推送**：能把每颗灯单独点亮（自定义效果靠它）
  - 灯位数和按键数**不一定相等**：VEGA108 是 108 键，但协议里逐灯数组是 128 个灯位（512 字节 ÷ 4），多出来的可能是侧灯/指示灯/未装配位
  - 先数清楚协议要求多少个灯位，再决定 `KEYS` 填多少
- [ ] **7. 建 layout JSON**：键位编号 + 坐标
- [ ] **8. 改 app.py 常量**：VID/PAGES/命令号/模式表
- [ ] **9. 改 index.html**：按钮、键码表、键盘图
- [ ] **10. 跑通**：点灯效、读状态、预览动起来、改键生效

**卡在哪一步就停在哪一步，不要跳**——协议没通就改界面是浪费时间。

## 6. 已知的坑（从 VEGA108 踩出来的，别的键盘大概率也有）

1. **写灯效可能必须带一个"驱动模式"字节**（我们是 `driverSetting=255`），少了会被丢弃或行为异常
2. **"临时写"和"持久写"是两条命令**：临时数据几秒后被固件动画覆盖；要留住颜色必须用持久命令
3. **读响应要跳过噪音包**：设备会主动推状态，响应淹没在里面，必须按命令号匹配，不能读一包就完事
4. **无线通道读状态会超时**：能跳过就跳过，靠本地保存的状态回填界面
5. **Fn 键是特殊层**：改了它的键值会连带废掉 Fn 组合，别动
6. **改键是整表写**：一次写全部键位，只改一个也要把其余键的当前值一起发过去
7. **打包**：PyInstaller 要 `collect_data_files('webview')`，否则前端 `window.pywebview.api` 是空对象

## 7. 交付标准

适配完成 = 下面全部成立：

- 打开软件能识别键盘，显示当前灯效
- 点灯效按钮，键盘真的变
- 实时预览能读到逐灯颜色
- 逐灯自定义（音乐律动 / 单键改色）能推
- 改键能读写
- 关掉软件，键盘回到自带灯效
